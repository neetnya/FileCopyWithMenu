# FileCopyWithMenu · 目录树复制工具

一个 Windows 桌面小工具：左右两栏目录树，左侧多选文件/文件夹（选中文件夹会递归包含其下所有内容），
点中间的 **【→】** 就把目录结构和文件一起复制到右侧目录。

典型的适用场景：把散落在多个目录里的东西按原有层次整理到一个目标位置——比如把若干工程目录里的
素材、素材的子目录结构，一次性"搬"进归档盘，而不用在资源管理器里一层层展开复制。

- 界面：C# / WPF（`net8.0-windows`），**零第三方依赖**（只用 BCL + WPF）
- 架构：`Core/` 是纯逻辑、不引用 WPF，可以脱离界面单独编译与测试
- 设计取向：**不做任何记忆**——每次打开都是干净的空状态，不保存也不恢复任何历史状态

## 1. 特性一览

- **左右两栏目录树**，中间一个圆形的 **→** 复制按钮，语义一目了然
- **多选**：Ctrl 点选切换、Shift 点选范围、Shift+↑/↓ 扩展选区、Ctrl+A 全选可见项、Space 切换、Esc 清空
- **选中文件夹 = 递归**：整个子树的目录结构和文件都会被复制
- **保留相对路径**：每个选中项按"相对左侧根目录的路径"落到右侧，不改变层级关系
- **快捷全展开 / 全折叠**：大目录树分块异步展开，界面不卡死
- **三种冲突策略**：覆盖 / 跳过 / 自动重命名（`名称 (1).ext`）
- **可选保留时间戳**：文件沿用源文件的修改时间与创建时间，文件夹沿用源文件夹的修改时间
- **长路径支持**：路径超过 260 字符也能复制（`\\?\` 前缀 + 清单 `longPathAware`，实测 338 字符正常）
- **安全扫描**：目录联接点 / 符号链接目录不递归，避免无限递归与成环
- **复制前先完整扫描**：因此"目标目录位于源目录内部"也不会陷入自我复制的死循环
- **实时进度与可取消**：进度条 + 状态文本 + 彩色日志，随时可中断
- **高 DPI**：Per-Monitor V2，多显示器缩放切换不糊

## 3. 快速开始

### 方式一：双击 `launch.bat`（推荐）

`launch.bat` 会先找 `dist\FileCopyWithMenu.exe`；如果不存在，自动调用 `build.bat` 构建，然后启动。

### 方式二：直接运行

```bat
dist\FileCopyWithMenu.exe
```

### 方式三：手动构建

```bat
cd /d D:\tools\FileCopyWithMenu
"%ProgramFiles%\dotnet\dotnet.exe" build FileCopyWithMenu.csproj -c Release -o dist
```

构建产物：`dist\FileCopyWithMenu.exe`（约 150 KB，加上同目录的 `.dll` / `.deps.json` / `.runtimeconfig.json`）。
`build.bat` 与 `launch.bat` 都做了容错：找不到 `dotnet` 时回退到 PATH 上的 `dotnet`。

### 上手三步

1. 左侧点【浏览…】选源目录，右侧点【浏览…】选目标目录
2. 在左侧树里多选要复制的东西（点文件夹 = 连同里面全部内容）
3. 点中间的 **→**（或按 **Ctrl + →**）

### ① 左栏 = 源目录

- **目录框**：手输路径后按 **Enter** 载入；按【浏览…】用系统目录选择器
- **刷新**：重新读取当前目录（外部新增/删除文件后同步）；**上级**：切到父目录
- **树节点显示**：图标 + 名称 + 右侧副信息
  - 文件夹：文件夹图标
  - 文件：文档图标 + `大小 + 修改时间`
  - 目录链接 / 联接点：链接图标 + `目录链接`（这类节点不递归、也没有展开箭头）
  - 读不了的目录：会插入一个警示样式的子节点 `⚠ 无法读取：原因`，同时面板标题右侧提示读取失败
- **排序**：每层都是「文件夹 → 目录链接 → 文件」，组内按**自然排序**（所以 `第2章` 排在 `第10章` 之前）
- **标题右侧信息区**：显示"共 N 项"或选中统计"已选 N 项（X 文件夹 / Y 文件，合计 Z）"

### ② 右栏 = 目标目录

结构与左栏完全一致，用作目标位置与结果预览。它在复制完成后会自动刷新并（若勾选了
"完成后定位到目标"）展开到第一个复制过去的条目，方便一眼确认落点。

### ③ 中间栏

- 顶部小字：当前已选数量（"未选择"/"已选 N 项"）
- 圆形 **→** 按钮：执行复制（快捷键 **Ctrl + →**）

## 6. 复制规则（核心语义）

一句话：**每个选中项，按"它相对于左侧根目录的路径"，原样复制到右侧根目录下的同一相对位置。**

设左侧根目录为 `D:\A`、右侧根目录为 `E:\B`：

| 左侧选中的东西 | 结果 |
| --- | --- |
| 文件 `D:\A\docs\a.txt` | `E:\B\docs\a.txt` |
| 文件夹 `D:\A\docs`（含 `a.txt`、子目录 `img\` 等） | `E:\B\docs\a.txt`、`E:\B\docs\img\...` —— 整个子树一起过去 |
| 左侧**根目录本身** `D:\A` | `E:\B\A\...`（目标下会多出一层同名目录，这是刻意的） |
| 同一层级的多个选中项 | 各自按相对路径落位，公共层级自动合并 |
| 选中深层目录 + 它的父目录 | 会出现重复条目（父目录本就包含它），重复写入的部分按冲突策略处理 |

其它配套规则：

- **目录结构由文件路径推导**：源里只有文件、没有空目录时，父目录会自动建出来
- **空文件夹**：默认也会建出来（可关闭，见下一节）
- **目录名被同名文件占用**：也按冲突策略处理（覆盖 = 删掉那个文件后建目录；跳过 = 跳过整棵子树并记日志；重命名 = 换新名字建目录）
- **源目录 = 目标目录**：直接拒绝并提示
- **目标目录位于源目录内部**：先弹确认框（可能造成重复嵌套），确认后才继续
- **目录联接点 / 符号链接目录**：**不递归**，跳过并在日志里计数说明（见"实现要点"）
- **指向文件的符号链接**：按普通文件处理（复制其内容）

### 为什么要"相对左侧根目录"

这样你才能在不改变内部层级的前提下，把一批来自不同子目录的东西整体挪到另一个盘上——
保留相对结构是这类"整理/归档"任务的关键，否则子目录里的同名文件会互相撞车或层次全乱。

## 7. 选项详解

顶栏四个选项，全部**不记忆**，每次启动都是下面写的默认值：

### 冲突时：覆盖 / 跳过 / 自动重命名（默认：覆盖）

目标位置已经存在同名项时怎么办：

| 策略 | 行为 |
| --- | --- |
| **覆盖** | 直接替换目标文件（内容、时间戳都按本次复制的规则来） |
| **跳过** | 保留目标里已有的，不动它；该文件计入日志的"跳过"数 |
| **自动重命名** | 新文件改成 `名称 (1).ext`、`名称 (2).ext`…… 不覆盖任何已有内容 |

### ☑ 复制空文件夹（默认：勾选）

- **勾选**：源目录里的空文件夹，在目标里也建出来（目录结构完整）
- **不勾选**：只把"最终含有文件"的那些目录建出来，源里的空文件夹会被忽略

### ☑ 保留时间戳（默认：勾选）

控制复制后的时间属性，**不影响文件内容**：

- **勾选**：文件沿用源文件的**修改时间**和**创建时间**；文件夹沿用源文件夹的**修改时间**
- **不勾选**：时间都变成"复制这一刻"

典型用途：照片、文档、代码归档后按日期排序不会乱；增量备份时也能靠时间判断新旧。

> 实现上有个细节：文件夹的时间必须在**所有文件写完之后、由深到浅**还原。
> 否则"先把目录时间设好、之后又往里写文件"会把目录时间顶回当前时刻。本程序按深度逆序处理。

### ☑ 完成后定位到目标（默认：勾选）

复制完成后，右栏自动刷新并展开定位到第一个复制过去的条目，省得自己去找。

## 8. 日志与错误处理

- 日志区每行都带时间戳，**失败信息标红、完成/成功信息标绿**
- 每次复制开始时会打印：源目录、目标目录、选中项数、以及本次生效的三个选项（覆盖/空目录/时间戳）
- 结束时打印汇总：`成功 N 个文件（大小），跳过 X，失败 Y，新建目录 Z，用时 T`
- 有文件失败时会额外弹窗提示（细节看日志）
- 日志区最多保留 3000 行，超出后丢弃最早的，避免长时间运行后内存膨胀
- 三个按钮：**清空**（清日志显示）、**打开目标目录**（在资源管理器里打开右侧目录）、
  **打开日志文件**（打开崩溃日志，见下节）

复制失败最常见的原因：目标文件被其他程序占用、目标磁盘写满、目标路径权限不足、
源文件在复制过程中被删除。这些都不会中断整个任务——单个条目失败会被记录，其余照常复制。

## 9. 本程序没有任何记忆功能

这是一个**刻意的设计选择**（按使用要求）：

- 启动时**左右两侧都是空的**，不预加载、不恢复上次用过的任何目录，路径框为空、无任何选中项；
  两侧只显示一行居中提示「点【浏览…】选择源目录 / 目标目录」
- 窗口尺寸、窗口位置、是否最大化——每次都用 XAML 里的默认值（1340×800、居中）
- 冲突策略、三个复选框——每次都是上表里的默认值
- 不写任何配置文件；程序**不读取**任何历史状态，即使磁盘上恰好存在疑似配置文件

唯一会写盘的是崩溃日志：

```
%APPDATA%\FileCopyWithMenu\error.log
```

它只在程序发生**未处理异常**时追加（用于排查问题），不参与任何状态恢复，也不影响每次启动的行为。

```

├─ MainWindow.xaml             主窗口布局：选项条 / 三栏主体 / 日志区 / 状态栏

├─ Core/                       纯逻辑层，不引用 WPF
│  ├─ PathUtil.cs              长路径 `\\?\`、路径关系判断、条目类型识别、大小格式化、自然排序
│  ├─ FileNode.cs              树节点 ViewModel：懒加载子节点、选中/当前状态、图标与副信息
```

## 11. 实现要点

给后续维护者的一些关键设计说明：

**长路径**
所有文件 IO 都经过 `PathUtil.Long()`，长度 ≥240 时补 `\\?\` 前缀（UNC 路径用 `\\?\UNC\`）；
同时 `app.manifest` 声明了 `longPathAware`。两者配合，不需要改注册表就能处理超过 260 字符的路径。

**目录联接点必须跳过**
Windows 上目录联接点（junction）和符号链接目录会被遍历当成普通目录，顺着走会无限递归——
用户配置目录下就有 10 个这种兼容性联接点（如 `Application Data` → `AppData\Roaming`）。
识别方式：`FileAttributes.ReparsePoint`。识别为链接的目录**不递归**，在树里标记为"目录链接"，复制时跳过并计数。

**先扫描完再复制**
复制前先把整个源枚举成"目录列表 + 文件列表"，然后才开始建目录、拷文件。
好处：即使目标目录位于源目录内部，也不会因为"边拷边扫"把新生成的文件再当成源而无限膨胀。

**树的懒加载与占位节点**
`FileNode` 只在需要时读子项。为了不显示无意义的展开箭头，只有"确实含有条目"的目录才挂占位子节点——
判断方式是只取第一个条目就停的廉价检查，所以空文件夹和文件都不会出现箭头。

**WPF TreeView 的多选**
原生 `TreeView` 不支持多选，这里没有用取巧的 hack：自定义了 `TreeViewItem` 的 `ControlTemplate`，
行背景由 `DataTrigger` 绑定节点 ViewModel 上的 `IsSelected` / `IsCurrent`（而不是容器自己的 `IsSelected`），
鼠标点击在 `PreviewMouseLeftButtonDown` 里自行处理并 `e.Handled = true`。因此容器回收（虚拟化
`Recycling`）也不会出现高亮错乱。点击展开箭头时会直接放行，交给箭头自己处理。

**全展开是分块异步的**
每加载 80 个文件夹就让出一次 UI 线程（`Dispatcher.Yield`），并设了 4 万个文件夹的上限，
避免误对一个超大目录点"全展开"时界面长时间无响应。

**选中的统计也是异步的**
选中后会在后台统计"多少文件夹 / 多少文件 / 合计多大"，并且上一次统计会被新的选择取消
（`CancellationTokenSource`），所以连续快速点选不会积压任务。

**进度回调**
`CopyEngine` 通过 `IProgress<CopyMessage>` 报告日志与进度；WPF 的 `Progress<T>` 会自动把回调
marshal 回 UI 线程，界面代码不需要自己切线程。复制本身跑在 `Task.Run` 里，随时可取消。

**其它**
树是虚拟化的（`VirtualizingPanel.IsVirtualizing` + `Recycling`）；节点排序用自然排序
（`第2章` 排在 `第10章` 前面）；复制的是内容，不搬运 NTFS ACL、备用数据流等属性。

## 12. 已知限制与注意事项

- **不提升权限**：目标目录需要管理员权限时会失败（日志会写明原因），不会自动弹 UAC
- **不做加密 / 校验**：复制即字节拷贝，没有哈希校验、没有断点续传、没有增量比对
- **不保留 NTFS 高级属性**：ACL、备用数据流（ADS）、硬链接关系、稀疏属性都不复制
- **符号链接不重建**：指向文件的链接按普通文件（复制内容）处理；指向目录的链接一律跳过
- **被占用的文件会失败**：目标文件被其他程序锁定时无法覆盖，会在日志里记失败
- **同名合并是"按文件"的**：同目录下的同名文件按冲突策略处理，不存在"整目录原子替换"
- **全展开有上限**：单次全展开最多加载 4 万个文件夹（防止误操作卡死），到上限会提示
- **删除操作**：本工具只复制、不删除源文件；"覆盖"策略会删除目标位置的同名文件

## 14. 常见问题

**双击 `launch.bat` 没反应？**
多半是缺少 .NET 8 Desktop Runtime。命令行运行 `dist\FileCopyWithMenu.exe` 能看到报错信息，
或者检查 `%APPDATA%\FileCopyWithMenu\error.log`。

**为什么打开时两边都是空的，上次的目录去哪了？**
这是刻意设计——本程序不做任何记忆（见第 9 节）。

**为什么有的（空）文件夹没有展开箭头？**
没有子项的东西不显示箭头，避免点了没反应。文件夹里有内容时才出现箭头。

**为什么复制了几万个文件后界面还流畅？**
复制在后台线程执行，进度通过 `IProgress` 回传；树是虚拟化渲染的，只有可见区域有控件。

**选了一个很大的目录，复制前想先知道有多少文件？**
选中后左栏标题右侧会自动统计（文件夹数 / 文件数 / 合计大小），统计过程不阻塞界面。

**能复制到 U 盘或网络位置吗？**
可以，就是普通的文件写入。网络位置慢一些，且个别错误（连接中断）会记为该条目失败。

**源目录和目标目录相同，或者目标在源里面？**
相同会直接拒绝；目标在源内部会先弹确认框，确认后继续（内部机制保证不会无限自我复制）。

**长路径（超过 260 字符）会出问题吗？**
不会。IO 全部走长路径前缀，实测 338 字符的路径可以正常复制，也不必修改系统注册表。
